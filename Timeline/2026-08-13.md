# 2026-08-13 — Register Flow: Role-Aware Signup

## Files Changed

### `apps/web/src/app/register/actions.ts`
- Added `SIGNUP_ROLES` constant (patient, doctor, nutritionist, trainer, family_member, caregiver) — no admin at signup
- Added `SignupRole` type and `PROFESSION_ROLES` / `PROFESSION_LABELS` sets
- `createPatientAccount` now accepts `role` in input and writes `requestedRole` to `User`
- For profession roles (doctor/nutritionist/trainer): upserts a `ProfessionType` and creates a `UserProfession` row with `status: "PENDING"` (verification queue)
- Return type changed from `{ ok: true }` → `{ ok: true; pendingVerification: boolean }`

### `apps/web/src/app/register/page.tsx`
- Imports `SIGNUP_ROLES` and `SignupRole` from actions (role list now driven by the server constant)
- Role dropdown now renders from `SIGNUP_ROLES.map()` — replaces hardcoded Patient/Doctor/Caregiver/Other options
- Role select is now `required`; validation added client-side before submit
- `role` passed through to `createPatientAccount`
- Added `noticeCanContinue` state — if profession pending but session exists, shows "Continue to dashboard →" link
- Notice block split into `<p>` + conditional link (was a plain string)
- Contextual hint text under role select for professions ("pending review") and family/caregiver roles ("link later from dashboard")
